# Crop recommendation

Given soil nutrients (N, P, K), temperature, humidity, pH and rainfall, this project predicts
which of 22 crops suits those conditions. It is a small multi-class classification problem on
the 2200-row crop recommendation dataset.

The project started as a Spark MLlib notebook (`notebooks/exploration.ipynb`). The training
and prediction code here is a scikit-learn rewrite of that pipeline: same dataset, same seven
features, same family of models, but with a reproducible split, cross-validation and a saved
model that can be used from the command line.

## Layout

    crop_recommendation/         package: data loading, models, evaluation, train, predict
    train.py                     train the models, pick the best one, write reports
    predict.py                   predict a crop from a set of readings
    scripts/download_data.py     fetch the dataset from a public mirror
    data/                        where the CSV goes (not committed, see data/README.md)
    notebooks/exploration.ipynb  the original Spark exploration, kept as a record
    models/                      saved model, regenerated by train.py
    reports/                     metrics, classification report, confusion matrix

## Setup

    git clone https://github.com/vivekkumarq/crop-recommendation.git
    cd crop-recommendation
    python -m venv .venv
    .venv\Scripts\activate          # on Linux or macOS: source .venv/bin/activate
    pip install -r requirements.txt

Then get the dataset. It is not committed; `data/README.md` explains where it comes from and
what shape it must have. The quick route:

    python scripts/download_data.py

That writes `data/Crop_recommendation.csv` and checks the schema against what the code
expects. The canonical source is the Crop Recommendation Dataset on Kaggle.

## Training

    python train.py

This loads the CSV, makes a stratified 80/20 train/test split with seed 42, cross-validates
four candidate models on the training split only, refits the best one on the full training
split, and scores it once on the held-out test set. It writes:

- `models/crop_model.joblib` - the fitted pipeline plus the feature list, label list and seed
- `reports/metrics.json` - cross-validation scores for every model and the test metrics
- `reports/classification_report.txt`, `reports/confusion_matrix.csv`,
  `reports/confusion_matrix.png`, `reports/feature_importance.csv`

Flags: `--data`, `--model-path`, `--report-dir`, `--test-size`, `--folds`, `--seed`,
`--no-plot`.

## Prediction

    python predict.py --n 90 --p 42 --k 43 --temperature 20.9 --humidity 82 --ph 6.5 --rainfall 203

    recommended crop: rice
    top 3:
      rice           0.995
      jute           0.005
      coffee         0.000

`--csv path.csv` predicts for every row of a file that has the seven feature columns.

## Results

Measured on the 2200-row dataset with seed 42: 1760 training rows, 440 test rows. The table is
5-fold stratified cross-validation accuracy on the training split. The classes are balanced at
100 rows each, so accuracy is a fair summary here.

| model                | CV accuracy       |
|----------------------|-------------------|
| Gaussian naive Bayes | 0.9949 +/- 0.0042 |
| Random forest        | 0.9943 +/- 0.0048 |
| Decision tree        | 0.9852 +/- 0.0068 |
| Logistic regression  | 0.9682 +/- 0.0066 |

Gaussian naive Bayes wins by a hair and is the model that gets saved. On the held-out test set
it scores 0.9955 accuracy and 0.9954 macro F1. Two of the 440 test rows are wrong, both the
same confusion: two rice samples predicted as jute. Every other crop is classified perfectly.

The gap between the top two models is well inside the fold-to-fold spread, so this is not
evidence that naive Bayes is genuinely better than a random forest here. The dataset is clean
and well separated, and several models saturate it.

Permutation importance for the saved model on the test set, that is, the mean drop in accuracy
when one column is shuffled:

| feature     | importance |
|-------------|------------|
| humidity    | 0.451      |
| K           | 0.434      |
| rainfall    | 0.359      |
| P           | 0.181      |
| N           | 0.153      |
| temperature | 0.083      |
| ph          | 0.052      |

Humidity, potassium and rainfall carry most of the signal. pH matters least, which contradicts
the claim in the earlier version of this README that pH was one of the most influential
features.

## What changed from the notebook

The notebook is kept as it was under `notebooks/`, but the code here does not reproduce its
problems:

- Its first split was `randomSplit([0.7, 0.3])` with no seed and no stratification, so the
  numbers were not reproducible. Splits here use seed 42 and stratify on the crop label.
- Models were judged on a single split. Here every candidate is scored with 5-fold stratified
  cross-validation on the training data, and the test set is touched once, at the end, by the
  selected model only.
- The notebook's decision tree scored 0.41 because Spark's default depth of 5 cannot separate
  22 classes, and it was printed next to the random forest as if the comparison meant
  something. Grown to full depth, the tree reaches 0.985.
- Its `StandardScaler` was fitted on the whole dataset. Scaling here lives inside a
  `Pipeline`, so it is fitted on training folds only and never sees held-out rows.
- Logistic regression was run with `maxIter=5` and had not converged (0.834). With enough
  iterations it reaches 0.968.
- Spark's multinomial naive Bayes was applied to continuous features, which is the wrong
  likelihood for them. Gaussian naive Bayes is used instead.
- The label column was named `genderIndex`, left over from a template, and the label encoding
  was fitted before the split.
- The SVM section never ran; it failed on a missing `features` column, so no SVM is included
  here.

## Requirements

Python 3.10 or later and the pinned packages in `requirements.txt`: pandas, numpy,
scikit-learn, scipy, joblib, matplotlib. The notebook additionally needs `pyspark` and
`findspark`, which the training and prediction code does not.
